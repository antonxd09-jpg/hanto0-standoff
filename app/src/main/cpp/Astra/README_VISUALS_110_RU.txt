ASTRA: ТЕСТОВЫЙ ПОРТ VISUALS НА 1.1.0 ARM64

Это исходный проект для самостоятельной сборки и проверки в игре.
Android-сборка и игровой тест не выполнялись. Статические проверки не
доказывают, что все вызовы и хуки сработают в живом процессе.

Что подключено к активному коду:
- Профиль Standoff2-1.1.0-arm64-visuals и границы ELF нового libunity.so.
- TypeInfo и имена классов цепочки мира, игрока, трансформов, модели,
  статов, оружейного компонента и оружия.
- Методы обновления игрока odq.fixo (виртуальный слот 50), позиции odq.apss.
- Native Camera::GetMain 0x591B4FC; матричные кэши +0x70 / +0xB0
  подтверждены дизассемблированием новой библиотеки.
- C API обёртки IL2CPP, новая разметка Class / MethodInfo / FieldInfo.
- Поля встроенного WeaponContext, включая ActiveWeapon +0x80.
- Адреса Third person / Camera test и сигнатура его хука.
- Hitlog: ukb.bros, точка 0xAA3EAFC после формирования PlayerDamageEvent
  на стеке; killlog: xdf.pvps, точка 0xA78D3CC.
- Unity / GCHandle / текстурные методы GPU Night mode.
- nativeInjectEvent 0x5AC2F20, найден по JNI-таблице с сигнатурой
  (Landroid/view/InputEvent;I)Z.

Идентификация версии:
Проверяется GNU Build ID 69815f2befe135c2 по заметке ELF.
Несовпадающий бинарник блокирует запуск ESP runtime и Java input hook.
Проверка не отключает отрисовку GUI, но Java input hook блокируется.

Config:
Unity found / waiting libunity.so, base, имя профиля, проверка Build ID,
ESP status, число игроков и проекций, камера ready / waiting, счётчики
кэша камеры, состояния aim / ESP / hitlog hooks и время кадра.
Две вкладки Visuals / Config и постоянный кликабельный ватермарк сохранены.
Кнопка unload по-прежнему сообщает о недоступной выгрузке: реальный unload
в этот этап не входил.

Ограничения области работ:
Файлы features/aim, включая offsets.hpp, побайтово сохранены.
Aim / Silent / Anti-Aim не портированы и не показываются в GUI.
Общие таблицы классов / IL2CPP обновлены для работы Visuals.
Неподключённый Chams не портирован; исходный файл сохранён.
Другие неиспользуемые текущим GUI legacy-записи перечислены в
checks/legacy_entries_not_ported.json. Их нельзя считать адресами 1.1.0.
Старые резервные файлы проекта сохранены; активная точка входа использует
jni/src/ui/kazakh/menu.hpp. Дампов и старых obj/libs в архиве нет.

Проверки:
python checks/verify_offsets_110.py /path/to/1.1.0/dump
python checks/verify_gui.py
Нужны Python 3 и g++ для изолированных проверок C++ на хосте.
Первая проверяет хеши исходных данных, архитектуру и Build ID, ELF-диапазоны,
точные TypeInfo/name пары, RVA, байты guard-сигнатур и синтаксис offsets.hpp.
Также исполняется настоящая функция проверки профиля на правильном ID,
изменённом ID, повреждённой заметке ELF и недопустимом адресе.
Вторая запускает настоящую функцию ватермарка с Dear ImGui без рендерера.
Это не сборка libastra.so.

При первом тесте: проверь Config -> Binary profile, затем отдельно ESP,
Third person, Hitlog и GPU Night mode. Статус waiting при отсутствии матча
или ещё не созданных игровых объектов сам по себе не доказывает ошибку.
Нужны фактические состояния и лог/краш-лог для диагностики проблем запуска.
