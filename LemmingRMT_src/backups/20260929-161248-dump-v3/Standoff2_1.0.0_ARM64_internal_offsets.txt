6. ARM64 MANAGED LAYOUT BASICS
======================================================================

Il2CppObject:
  +0x00 Il2CppClass* klass
  +0x08 MonitorData* monitor
  +0x10 first instance field

Il2CppString:
  +0x10 int32 length
  +0x14 UTF-16 characters

Il2CppArray:
  +0x10 bounds pointer
  +0x18 uintptr_t max_length
  +0x20 vector/data

System.Collections.Generic.List<T>:
  +0x10 T[] _items
  +0x18 int32 _size
  +0x1C int32 _version
  +0x20 object _syncRoot

Never reuse ARM32 +0x08 object fields, +0x0C array length, +0x10 array data,
or +0x08/+0x0C List offsets in ARM64 code.

7. WORLD AND PLAYER RESOLUTION
======================================================================

Status: RUNTIME_REQUIRED.
No verified static ClientWorld singleton exists; VContainer or heap discovery is
required.

Abstract type-based path:

  world = heap/VContainer object where
          object->klass == CLASS(CLIENTWORLD_NJH_TYPEINFO_SLOT)

  registry = FIELD_BY_TYPE(world, CLASS(REGISTRY_GAT_TYPEINFO_SLOT))
  storage  = FIELD_BY_TYPE(registry, CLASS(STORE_GZX_TYPEINFO_SLOT))
  allObjects = FIELD_BY_CONTAINER_TYPE(storage, NetObject collection)

  items = allObjects + List._items(+0x10)
  count = allObjects + List._size(+0x18)

  player = item where object->klass == CLASS(PLAYER_AKE_TYPEINFO_SLOT)

Local player:
  localActor = world -> transport(hbu) -> actor(stn)
  localPlayer = player whose NetObjectId.OwnerId == localActor.ActorId

Do not use OwnerId to decide team. OwnerId identifies the owning actor.

Required runtime validations:
  - list count is sane (0..4096);
  - every item/object/class pointer is readable;
  - class matches player ake before reading player fields;
  - compare actor id and owner id using field metadata, not ARM32 offsets.

  teamOffset = FieldInfo.offset(WeaponContext field name == "Team")
  team = *(uint8_t*)(weaponPart + contextOffset + teamOffset)

10. SILENT AIM
======================================================================

Status: NOT_READY.

All old silent RVAs from 0.39.2 are invalid, including the old rotation ICall slot,
shot function, code cave, .bss scratch address and forward/right/up return hooks.

Server-authoritative lag compensation means changing only a local Ray or camera
rotation is unlikely to define the registered hit. Current working hypothesis:

  selected target angle
    -> replace view angle in current owv command
    -> preserve rendered local camera angle if desired
    -> command serializer/send
    -> server reconstructs shot from tick/history

Required discoveries before implementation:
  SILENT_1 = exact current-command owner field in ClientWorld
  SILENT_2 = exact owv tick/view/buttons offsets via FieldInfo and live trace
  SILENT_3 = owv serialization function RVA
  SILENT_4 = command send/queue function RVA
  SILENT_5 = proof that modified command angle affects server-confirmed hit
  SILENT_6 = restore/render separation without corrupting subsequent commands

Related but insufficient offsets:
  INPUT_COMMAND_OWV_TYPEINFO_SLOT=0xC1C3568
  PHYSICS_RAYCAST_RVA=0x538BD0C
  PHYSICS_RAYCAST_NON_ALLOC_RVA=0x538BD24

15. RUNTIME SAFETY / VALIDATION RULES
======================================================================

For every TypeInfo slot:
  addr = libunity_base + slot_rva
  wait for metadata initialization
  klass = *(uintptr_t*)addr
  verify pointer readable
  verify klass name/namespace/TypeDef/instance_size

For every object:
  verify object and object->klass are readable
  verify expected class before reading fields
  verify collection counts before indexing
  verify strings/arrays/lists using ARM64 layouts

For every CANDIDATE field:
  discovered = il2cpp_field_get_offset(FieldInfo)
  use value only when discovered == candidate
  otherwise log the discovered value and update this profile

For every native RVA:
  use only when libunity SHA-256 matches
  use exact calling convention/signature
  disable feature on pointer/prologue/range mismatch
